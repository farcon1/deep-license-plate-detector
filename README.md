# Deep License Plate Detector

Магистерская ВКР по разработке системы детекции и локализации автомобильных номеров на изображениях с использованием глубоких нейронных сетей.

**Полное название ВКР (RU)**  
«Разработка системы детекции и локализации автомобильных номеров на изображениях с применением глубоких нейронных сетей»

**Полное название ВКР (EN)**  
«Development of a Deep Learning-Based System for Vehicle License Plate Detection and Localization»

---

## 1. Краткое описание проекта

**Deep License Plate Detector** - программно-экспериментальная система автоматического обнаружения, локализации и распознавания автомобильных номерных знаков на изображениях.

Проект разработан в рамках магистерской выпускной квалификационной работы и объединяет:

- методы компьютерного зрения;
- нейросетевую детекцию объектов;
- специализированное OCR-распознавание;
- экспериментальную оценку качества;
- end-to-end инференс;
- web-интерфейс;
- REST API;
- Docker-контейнеризацию.

Система реализует полный ALPR-пайплайн: от исходного изображения автомобиля до структурированного результата с координатами номерного знака, crop-изображением, распознанной строкой и значениями уверенности моделей.

---

## 2. Назначение системы

Проект предназначен для исследования и демонстрации полного цикла построения системы автоматического распознавания автомобильных номерных знаков.

Основной сценарий работы:

```text
Исходное изображение автомобиля
        ↓
YOLO-детекция области номерного знака
        ↓
Формирование crop-изображения
        ↓
Нормализация входа для OCR
        ↓
ResNet34 OCR
        ↓
Декодирование символьной последовательности
        ↓
Визуализация и структурированный результат
````

Система может использоваться как:

* исследовательский прототип для ВКР;
* демонстрационное web-приложение;
* основа для дальнейшего развития ALPR-сервиса;
* экспериментальная платформа для сравнения методов детекции и OCR.

## 5. Архитектура системы

Архитектура проекта построена по модульному принципу. Каждый компонент отвечает за отдельный этап обработки данных или инференса.

```text
┌──────────────────────────────┐
│ Исходное изображение          │
└──────────────┬───────────────┘
               ↓
┌──────────────────────────────┐
│ YOLO-детектор                 │
│ Локализация номерного знака   │
└──────────────┬───────────────┘
               ↓
┌──────────────────────────────┐
│ Формирование OCR crop         │
│ bbox clipping, crop, resize   │
└──────────────┬───────────────┘
               ↓
┌──────────────────────────────┐
│ OCR ResNet34                  │
│ Распознавание 7 символов      │
└──────────────┬───────────────┘
               ↓
┌──────────────────────────────┐
│ Итоговый результат            │
│ text, bbox, confidence, image │
└──────────────────────────────┘
```

Ключевая особенность системы заключается в разделении задачи на два связанных этапа:

1. **Детекция** - определение координат номерного знака на полном изображении.
2. **OCR** - распознавание символьной последовательности по выделенному crop.

Такой подход повышает интерпретируемость системы: ошибки можно анализировать отдельно на уровне локализации и отдельно на уровне распознавания.

## 8. Используемый датасет

В качестве основного набора данных используется **CCPD2019**.

Особенность CCPD заключается в том, что аннотация изображения закодирована непосредственно в имени файла. Из имени изображения извлекаются:

* координаты bounding box номерного знака;
* координаты четырех углов номерной пластины;
* индексы символов номерного знака;
* параметры яркости;
* параметры размытости;
* характеристики наклона.

Такой формат позволяет использовать один и тот же исходный набор данных для двух задач:

1. обучения модели детекции;
2. обучения OCR-модели распознавания символов.

## 9. Подготовка данных

Подготовка данных выполняется в несколько этапов.

### 9.1. Подготовка данных для детектора

Для обучения YOLO-детектора исходные аннотации CCPD преобразуются в формат YOLO:

```text
class_id x_center y_center width height
```

В рамках проекта используется один класс:

```text
license_plate
```

### 9.2. Подготовка OCR-датасета

Для OCR-модуля из исходных изображений формируются crop-изображения номерных знаков. Каждому crop соответствует символьная метка из семи позиций.

Используются разные режимы crop:

| Режим         | Назначение                                                  |
| ------------- | ----------------------------------------------------------- |
| `corners`     | Перспективное выравнивание по четырем углам номерного знака |
| `bbox`        | Вырезание по прямоугольному bounding box                    |
| `bbox_pad`    | Вырезание bbox с дополнительными полями                     |
| `bbox_jitter` | Искусственное смещение bbox для повышения устойчивости      |
| `yolo_crop`   | Crop, сформированный после работы YOLO-детектора            |

## 10. Классический CV baseline

Для получения нижней границы качества был реализован классический baseline на основе OpenCV.

Он использует:

* перевод изображения в grayscale;
* CLAHE для выравнивания контраста;
* SobelX для усиления вертикальных границ;
* бинаризацию;
* морфологические операции;
* поиск контуров;
* фильтрацию кандидатов по геометрическим признакам;
* выбор лучшего bbox по эвристическому score.

Результаты baseline показывают ограниченность классического подхода в условиях сложного фона, изменения освещения, наклона и размытия.

| Количество изображений      |  199 996 |
| Mean IoU                    | 0.195313 |
| Median IoU                  | 0.000000 |
| Success rate при IoU ≥ 0.50 | 0.240905 |
| Success rate при IoU ≥ 0.70 | 0.182294 |

## 12. OCR-модуль

OCR-модуль решает задачу распознавания семисимвольной строки номерного знака.

В качестве основной архитектуры используется **ResNet34** с несколькими независимыми классификационными головами. Каждая голова отвечает за фиксированную позицию символа.

Структура предсказания:

| Позиция | Назначение                            |
| ------: | ------------------------------------- |
|       0 | Провинция / региональный префикс CCPD |
|       1 | Буквенный символ                      |
|     2–6 | Буквенно-цифровая часть номера        |

Такой подход позволяет учитывать фиксированную структуру номерного знака и решать OCR как набор позиционных задач многоклассовой классификации.

## 13. Robust OCR

Финальная OCR-модель обучена на robust-датасете, который включает разные варианты crop-изображений. Это позволяет приблизить обучение OCR к реальному end-to-end сценарию, где вход OCR формируется не по идеальной разметке, а после работы детектора.

Параметры финального OCR-эксперимента:

| Параметр                    | Значение |
| --------------------------- | -------: |
| Архитектура                 | ResNet34 |
| Размер входного изображения | 320 × 96 |
| Количество эпох             |       50 |
| Batch size                  |       96 |
| Learning rate               |   0.0005 |
| Weight decay                |   0.0001 |
| Оптимизатор                 |    AdamW |
| Лучшая val full-accuracy    |   0.9936 |
| Финальная val full-accuracy |   0.9931 |
| Финальная val char-accuracy |   0.9990 |

### 13.1. Результаты robust OCR

| Режим оценки | Количество изображений | Char Accuracy | Full Plate Accuracy | Mean Confidence |
| ------------ | ---------------------: | ------------: | ------------------: | --------------: |
| `corners`    |                 199 996 |      0.999707 |            0.998150 |        0.999921 |
| `bbox_pad`   |                 199 996 |      0.999657 |            0.997650 |        0.999899 |
| `yolo_crop`  |                 199 996 |      0.999686 |            0.998050 |        0.999886 |

Наиболее важным для практического применения является режим `yolo_crop`, поскольку именно он соответствует сценарию, при котором OCR-модель получает crop-изображения после работы YOLO-детектора.

## 14. Сравнение экспериментальных режимов

| Эксперимент           | Проверяемая часть системы                |    Основная метрика | Значение |
| --------------------- | ---------------------------------------- | ------------------: | -------: |
| Classical CV baseline | Локализация номерного знака без обучения |    AP при IoU ≥ 0.5 | 0.075276 |
| YOLO detector         | Нейросетевая локализация номера          |             mAP@0.5 | 0.984449 |
| YOLO detector         | Нейросетевая локализация номера          |        mAP@0.5:0.95 | 0.611422 |
| OCR `corners`         | Распознавание на идеальных crop          | Full Plate Accuracy | 0.998150 |
| OCR `bbox_pad`        | Распознавание на bbox-crop с padding     | Full Plate Accuracy | 0.997650 |
| OCR `yolo_crop`       | Распознавание на crop после детектора    | Full Plate Accuracy | 0.998050 |

Отдельная строгая оценка полного end-to-end pipeline как единой метрики `Full Plate Accuracy` не смешивается с OCR `yolo_crop`, поскольку для такой оценки необходимо учитывать не только качество OCR, но и возможные пропуски детектора. В текущей экспериментальной конфигурации режим `yolo_crop` используется как наиболее близкая к реальному infer-сценарию оценка OCR после детекции.

## 15. End-to-end pipeline

End-to-end pipeline объединяет YOLO-детектор и OCR-модель в единую цепочку обработки.

Последовательность инференса:

1. Пользователь передает изображение автомобиля.
2. YOLO-детектор определяет область номерного знака.
3. Система выбирает наиболее уверенный bbox.
4. Координаты bbox ограничиваются границами изображения.
5. Формируется crop номерного знака.
6. Crop приводится к размеру `320 × 96`.
7. OCR-модель предсказывает семь символов номерной строки.
8. Система возвращает распознанный номер, bbox, crop и значения confidence.

Выходной результат включает:

| Поле               | Содержание                          |
| ------------------ | ----------------------------------- |
| `detected`         | Факт обнаружения номерного знака    |
| `bbox`             | Координаты найденной области        |
| `det_score`        | Уверенность YOLO-детектора          |
| `pred_text`        | Распознанная строка номера          |
| `plate_confidence` | Средняя уверенность OCR             |
| `char_confidences` | Уверенности по отдельным позициям   |
| `annotated_image`  | Изображение с визуализацией bbox    |
| `crop`             | Вырезанный фрагмент номерного знака |

## 16. Web-интерфейс

Проект содержит web-интерфейс на базе **FastAPI**.

Интерфейс позволяет:

* загрузить изображение автомобиля;
* выбрать режим работы;
* настроить параметры детектора;
* запустить инференс;
* увидеть найденный bbox;
* посмотреть crop номерного знака;
* получить распознанную строку;
* оценить confidence детектора и OCR.

Поддерживаемые режимы:

| Режим              | Назначение                                |
| ------------------ | ----------------------------------------- |
| Детекция + OCR     | Полная обработка изображения              |
| Только детекция    | Диагностика локализации номерного знака   |
| Только OCR по crop | Проверка OCR на заранее вырезанном номере |

## 22. Научно-практическая значимость

Проект демонстрирует полный цикл разработки системы компьютерного зрения:

* анализ предметной области;
* подготовку данных;
* построение baseline;
* обучение нейросетевого детектора;
* обучение специализированного OCR;
* повышение устойчивости OCR через robust crop generation;
* экспериментальную оценку;
* интеграцию моделей в end-to-end pipeline;
* разработку web-интерфейса;
* контейнеризацию infer- и train-контуров.

Практическая ценность проекта заключается в том, что результатом является не только набор обученных моделей, но и функционирующий программный прототип, пригодный для демонстрации, анализа ошибок и дальнейшего развития.

## 23. Ограничения текущей версии

Текущая версия системы имеет ряд ограничений:

1. Модели обучались на датасете CCPD2019.
2. OCR-модель ориентирована на структуру китайских номерных знаков из CCPD.
3. Для применения к номерным знакам других стран требуется дополнительная адаптация словарей и данных.
4. Качество полного end-to-end сценария зависит от согласованности детектора и OCR.
5. Система предназначена для изображений; поддержка видеопотока может быть реализована как дальнейшее развитие.
6. Для промышленного применения требуется дополнительное тестирование на реальных данных целевого региона.
